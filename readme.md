## 1) Problem — “TODO Core Service (Minimal Domain)”

**Domain model (given):**
```java
private String id;
private String title;
private String description;
private boolean completed;
```
- `id` is generated by infra; `completed` defaults to `false`.  
- Repository is provided: `getAll()`, `getById(id)`, `save(task)`, `deleteById(id)`.

---

## 2) Functions to Implement (service layer)

1) **Create Task** — `createTask(input) -> Result<Task>`  
   Defaults, validate (see §3), persist, return created task.

2) **Set Completed** — `setCompleted(id, completed: boolean) -> Result<Task>`  
   Find by `id`; error if missing; update `completed`, save, return.

3) **List Tasks (Filters + Sort)** — `listTasks(filter) -> Result<Task[]>`  
   Filters (all optional, AND-combined):  
   - `completed` (boolean)  
   - `search` (case-insensitive in `title` or `description`)  
   Sort: `TITLE_ASC` (default) or `ID_ASC`.

4) **Summary** — `summary() -> Result<Summary>`  
```json
{ "total": 0, "active": 0, "completed": 0 }
```

---

## 3) Validation Rules
- **title**: required, **trim**, length **1–120**; reject empty/whitespace-only.  
- **description**: optional; if present, length **≤ 500**.  
- On validation failure, return **error** with clear, field-specific message (don’t throw).

---

## 4) Constraints
- No external HTTP/DB; no adding new libraries.  
- Deterministic behavior; keep changes inside **service/logic**.

---

## 5) Sample Visible Cases
- **Create (OK):** `"title":"Submit report","description":"Q4 finance"` → returns task with `completed=false`, trimmed title.  
- **Create (Validation Error):** `"title":"   "` → error `title: required (1–120 chars)`.  
- **Set Completed:** existing `id` toggles `completed`; missing `id` → `task: not found`.  
- **List (Filters+Sort):** `{ "completed": false, "search":"list", "sort":"TITLE_ASC" }` → only matching tasks.  
- **Summary:** on three tasks `[2 active, 1 completed]` → `{ "total":3, "active":2, "completed":1 }`.
